# Databases
Oracle, MySQL, Loki and Redis are reached with commands, run with bash if they exist. Each takes no arguments: what to run goes on stdin, in a heredoc with a quoted delimiter, which keeps the shell away from `$`, quotes, backticks and backslashes. Each prints the whole result, nothing cut off, so cut it in the query itself or pipe it through head, and redirect a large result to a file and look at it there with head, grep or awk. Errors come back exactly as the database printed them; a non-zero exit means it failed, and stderr says why. They are read-only through the database account they connect as, so do not expect to change anything with them.

opencode-oracle-query <<'SQL'
SELECT sid, serial# FROM v$session WHERE username = 'SCOTT'
SQL

opencode-mysql-query <<'SQL'
SELECT id, `name` FROM users WHERE name = 'a$b'
SQL

opencode-loki-query --since 1h <<'LOGQL'
{app="api"} |= "error"
LOGQL

opencode-redis-query <<'REDIS'
HGETALL user:42
REDIS

SQL commands print CSV. For Oracle, learn a table's shape from the data dictionary (`all_tab_columns`) before writing the real query. opencode-loki-query prints one line of JSON per stream, with [nanosecond timestamp, log line] pairs; give the time range with `--since 1h` or `--start`/`--end` (RFC3339 with an offset), and use `--labels` and `--values LABEL` to find what can be selected. opencode-redis-query prints the reply the way redis-cli --raw does, one value per line; prefer `SCAN` with a MATCH pattern to `KEYS` on a large keyspace.
