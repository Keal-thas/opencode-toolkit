# java-lsp mcp server

Lives in `mcp-servers/java-lsp/`. An MCP server exposing seven Java code-intelligence tools — `java_definition`, `java_references`, `java_hover`, `java_implementation`, `java_document_symbols`, `java_workspace_symbols`, `java_diagnostics` — by spawning and driving a real `jdtls` (Eclipse JDT Language Server) process over its native LSP stdio protocol (`mcp-servers/java-lsp/lsp-client.js` is a from-scratch minimal LSP client: `Content-Length` framing, JSON-RPC correlation, the `initialize`/`initialized` handshake, `didOpen`/`didChange` document sync). Design rationale lives in `mcp-servers/java-lsp/README.md`'s "Design" section. Runs as `type: "remote"`/Streamable HTTP like `oracle`/`loki`, but keeps one persistent `jdtls` process (an `LspClient` singleton) alive for the server's whole lifetime instead of connecting per-request — LSP is a genuinely stateful session (project indexing alone takes real time), unlike Oracle/Loki's stateless per-call model.

Built because opencode's own built-in `jdtls` LSP integration only auto-detects a `java` on `PATH` (`which("java")` + a version check, no `JAVA_HOME`/override support) with no way to point it at a different JDK for the actual analysis — see `mcp-servers/java-lsp/README.md`'s "JDK version" section.

**Tested:** `mcp-servers/java-lsp/java-lsp.test.mjs` — tool listing, `java_document_symbols` finding the real parsed class/methods, `java_hover` resolving a real type signature, `java_references` finding a real declaration + call site (not a name-text grep), `java_workspace_symbols` fuzzy-matching the real symbol index, and a path-traversal rejection check. Run against the vendored `jdtls` 1.61.0 and a small real Java fixture file — not mocked. **Not yet wired into `./tests/run-all.sh`** — the docker/ sandbox's image has no JDK installed (jdtls itself is vendored and no longer the blocker, see `mcp-servers/TODO.md`); run manually on a machine with a JDK 21+ `java` and `python3` (see `mcp-servers/java-lsp/README.md`'s Status section for the exact prerequisites, including a test-only precondition). Also not exercised against a real multi-file Maven/Gradle project, only a single loose `.java` file.
