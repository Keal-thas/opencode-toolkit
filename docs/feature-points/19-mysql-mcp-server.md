# mysql mcp server

Lives in `mcp-servers/mysql/`. An MCP server exposing one tool, `mysql_query`, running SQL against a configured MySQL database — every call unconditionally wrapped in `START TRANSACTION READ ONLY` (the enforcement mechanism itself, not a keyword filter), one connection per request. That transaction blocks DML (`INSERT`/`UPDATE`/`DELETE`) unconditionally but not DDL (`CREATE`/`DROP`/`ALTER`, which implicitly commit first) — closing that residual gap needs the connecting account's own grants too, see `mcp-servers/mysql/README.md`'s "Recommended read-only account" section, including why the popular community MySQL MCP servers were passed over. Design rationale lives in that README's "Design" section (canonical, not duplicated here). Runs as a `type: "remote"`/Streamable HTTP server, same deployment shape as `mcp-servers/oracle/`.

**Tested:** `mcp-servers/mysql/mysql.test.ts` (see `tests/README.md`) — tool listing, a plain SELECT, the READ ONLY transaction unconditionally rejecting an INSERT (error 1792, confirmed even from a fully-privileged account), the same transaction *not* rejecting a CREATE TABLE and that table actually persisting (the documented DDL gap), a nonexistent-table error path, and a connection-failure regression. Runs as part of `./tests/run-all.sh` against the sandbox's real `mysql` service.
