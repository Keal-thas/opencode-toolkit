# redis mcp server

Unlike `mcp-servers/oracle/`/`mcp-servers/loki/`/`mcp-servers/mysql/`, there's no server code in `mcp-servers/redis/` — it's the official upstream `redis-mcp-server` PyPI package (source: `redis/mcp-redis` on GitHub), used unmodified, same "sight-unseen from its own README" stance as the Memory MCP server (`docs/feature-points/15-opencode-memory-mcp.md`). Why the official package instead of hand-rolling one like `mysql`, the read-only enforcement (a dedicated Redis ACL user, `+@read -@write` — confirmed against a real Redis 7 instance to genuinely deny `SET`/`DEL`/`FLUSHALL`/`EVAL`/`SORT ... STORE`, no MySQL-style DDL loophole), and a confirmed upstream bug (`REDIS_HOST`/`REDIS_PORT` env vars are silently discarded by the installed package — `--host`/`--port` have to be CLI args instead, `REDIS_USERNAME`/`REDIS_PWD` env vars are unaffected and stay off argv) all live in `mcp-servers/redis/README.md` (canonical, not duplicated here). Wired as `type: "local"` (opencode spawns it via `uvx`), not `type: "remote"` like the other three — the upstream package only supports stdio transport today.

**Tested:** `tests/integration/mcp-redis/redis.test.mjs` (see `tests/README.md`) — spawns the real package via `uvx` against the sandbox's real `redis` service, connected as the ACL-restricted `readonlyuser`: tool listing, a `get` retrieving a value seeded through an independent connection, that same account rejecting a `set` cleanly (confirmed not to have actually written, via the independent connection, not just trusting the tool's own error text), and `get` on a missing key returning a clean message. Runs as part of `./tests/run-all.sh`. Needs `uv`/`uvx` on the host (added to `docker/Dockerfile` for this — see `docker/docker-notes.md`'s "uv/uvx" section — and a real prerequisite for any actual deployment, see SETUP.md).
