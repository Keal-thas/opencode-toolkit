# system-prompt-tools.ts plugin

Source lives in `plugins/system-prompt-tools/system-prompt-tools.ts`. Hooks `experimental.chat.system.transform` to dump the fully-assembled system prompt actually sent to the model (all blocks, including opencode's own `<env>` block) to `~/.local/share/opencode/last-system-prompt.txt` on every request — the only way to confirm the override is really taking effect against the real model, since there's no other visibility into what gets sent. Written in TypeScript against `@opencode-ai/plugin`'s `Plugin` type (the official SDK), matching `plugins/hook-logger/hook-logger.ts`/`plugins/llm-review-gate/llm-review-gate.ts`.

**Packaging:** ships as its own npm package — `plugins/system-prompt-tools/package.json`, published to the public registry as `@kealthas-dev/opencode-system-prompt-tools`, referenced in `opencode.json`'s `plugin` array by bare name alone (no version, no path). opencode's own npm-plugin loader installs it itself on first use, caching the result under `$CACHE_DIR/packages/@kealthas-dev/opencode-system-prompt-tools@latest/` (SETUP.md step 4). `plugins/hook-logger/` and `plugins/llm-review-gate/` use the same mechanism as their own independent packages (SETUP.md step 5). See `docker/docker-notes.md`'s "Plugin loading" section for the npm-install mechanism's gotchas (a bad plugin name fails silently, leaving an empty cache dir) and CLAUDE.md's `plugins/` row for the current install mechanism. Tradeoff: editing `system-prompt-tools.ts` only takes effect once published as a new version — unlike `deploy/system-prompt.txt`'s live bind mount.

**Tested:** `tests/unit/system-prompt-tools.test.mjs` — dump content/header format (model/session/block-count), and that each request overwrites rather than appends (the dump always reflects the latest request).
