# llm-review-gate.ts plugin

Lives in `plugins/`. Gates `bash` tool calls behind an LLM safety review: before a command runs, it's sent to a hidden internal opencode session for an ALLOW/BLOCK verdict, layered on top of (not replacing) opencode's own permission config. Fails open on review errors/timeouts by default (`FAIL_OPEN_ON_ERROR`, configurable). Never reviews its own internal review session's own calls (no recursion). Written in TypeScript against `@opencode-ai/plugin`'s `Plugin` type (the official SDK) rather than an untyped raw hook object.

The review call runs under a dedicated `review-gate` agent (`deploy/opencode.json.example`, no `prompt` override, every tool permission denied except `review_verdict`, see below), not whatever the default primary agent is. This matters because a per-request `system` field is appended after an agent's configured `prompt`, not a replacement for it (verified against opencode dev-branch source, `packages/opencode/src/session/llm/request.ts`) — without `review-gate`, the review session would inherit `build`/`plan`/`general`'s full `system-prompt.txt` coding-agent persona ahead of the review instructions, and the model would reply with normal chat or tool calls instead of the expected verdict.

Each review runs in its own throwaway session, created right before the prompt call and deleted right after — not one long-lived session reused across every gated tool call. A session is opencode's only unit of model invocation, but it's also a stateful conversation: reusing one session would grow its message history by a command+verdict turn per review for as long as the plugin instance lives, silently inflating the context (and token cost) sent on every later review and contradicting the review prompt's own "judge this one command in isolation" framing. `session.create`/`session.delete` are cheap metadata calls, not model calls, so one-shot sessions don't add a second LLM round trip.

The verdict itself is recorded as a real function call, not just parsed from free text: the plugin registers a `review_verdict(allow, reason?)` custom tool (a plugin-registered tool is available to every agent by name like a built-in one, per `docs/opencode-docs-reference/custom-tools.mdx`, so it's denied globally in `deploy/opencode.json.example`'s top-level `permission` and allowed only for `review-gate`). `REVIEW_SYSTEM_PROMPT` tells the model to call it; `execute()` stashes the args in an in-memory map keyed by that review's one-shot session ID, and `review()` reads it back once `session.prompt()` resolves. If the model never calls the tool, `review()` falls back to the original ALLOW/BLOCK text-parsing logic, so a model or deployment where tool-calling doesn't cooperate still degrades to the old behavior rather than breaking. This is the one plugin in this repo with a real runtime dependency (`zod`, for the tool's argument schema) — every other plugin here only imports `@opencode-ai/plugin`'s types (erased at build time).

**Deployment:** own npm package at `plugins/llm-review-gate/` (`package.json`), published to the public npm registry as `@kealthas-dev/opencode-llm-review-gate` and referenced as a bare `@kealthas-dev/opencode-llm-review-gate` (no version) — opencode's npm-plugin loader installs it itself. Included by default in `deploy/opencode.json.example`'s `plugin` array despite changing real runtime behavior (an extra hidden model call before every `bash` invocation, unlike `hook-logger/`'s passive logging). Independently removable from `hook-logger/` — see `docs/feature-points/02-system-prompt-tools-plugin.md` for the mechanism.

**Tested:** `tests/unit/llm-review-gate.test.mjs` — ALLOW/BLOCK paths (both via the `review_verdict` tool call and via the text fallback, with the tool call taking precedence when both are present), non-gated tools skipped entirely, the in-flight self-recursion guard, fail-open on review error or an unparseable verdict, a regression guard that the review call's `agent` field is `review-gate`, that `review_verdict` is registered under the exact name the config grants permission for, and that each review creates and deletes its own one-shot session rather than reusing one. Driven with a fake opencode `client`, so no real session or model server is needed — the plugin's actual effect on a real model's tool-calling behavior hasn't been verified against a live deployment yet.
